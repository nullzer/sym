# Safety Helmet Video Analyzer

Мини-система для локального анализа видеозаписей землеройных работ и фиксации
эпизодов, где сотрудники находятся без защитных касок.

Система рассчитана на офлайн-запуск: видео, модель и отчетные файлы хранятся
локально, обращения к внешним сервисам не выполняются.

## Что умеет MVP

- принимает одно видео за запуск;
- выбирает кадры с заданной частотой, чтобы ускорить обработку;
- запускает локальный detector backend:
  - `onnx` для YOLO/ONNX-модели, размещенной в `models/`;
  - `color` как экспериментальный демонстрационный fallback без ML-модели;
- определяет кадры с признаками отсутствия каски;
- объединяет соседние кадры в эпизоды нарушения;
- сохраняет:
  - `analysis.json` с машинно-читаемым результатом;
  - `report.html` для просмотра человеком;
  - кадры-доказательства в `evidence/`.

## Этапы разработки

1. **MVP ingestion** - загрузка одного видео через CLI или локальную web-форму.
2. **Покадровая выборка** - обработка 1-5 кадров в секунду вместо всего потока.
3. **Локальная модель** - подключение ONNX/YOLO-модели для классов `person`,
   `helmet`, `no_helmet`.
4. **Правила нарушения** - отсутствие каски подтверждается несколькими соседними
   кадрами, чтобы уменьшить ложные срабатывания.
5. **Отчетность** - таймкоды, уверенность, причины, кадры-доказательства.
6. **Калибровка** - дообучение или настройка модели на реальных видео объекта.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install -e .
```

Для полностью офлайн-среды заранее перенесите wheel-файлы зависимостей и
установите их из локальной папки:

```bash
pip install --no-index --find-links ./wheels -r requirements.txt
pip install -e .
```

## Подготовка модели

Поместите модель в `models/helmet_detector.onnx`, а файл меток в
`models/labels.txt`.

Пример `models/labels.txt`:

```text
person
helmet
no_helmet
```

Поддерживаются YOLO-подобные ONNX-выходы формата:

- `[1, N, 4 + classes]`;
- `[1, 4 + classes, N]`;
- `[1, N, 5 + classes]`.

Если у модели другие выходы, нужно адаптировать парсер в
`src/safety_helmet_analyzer/detectors.py`.

Подробная инструкция по источникам модели, обучению, экспорту в ONNX,
офлайн-переносу и настройкам находится в
[`docs/model-and-operations-guide.md`](docs/model-and-operations-guide.md).

## CLI-запуск

```bash
python3 -m safety_helmet_analyzer analyze path/to/video.mp4 \
  --config config/default.json \
  --output reports/run-001
```

Для демонстрационного режима без ONNX-модели:

```bash
python3 -m safety_helmet_analyzer analyze path/to/video.mp4 \
  --backend color \
  --output reports/color-demo
```

Цветовой режим использует эвристики OpenCV и не подходит для промышленной
приемки, но помогает проверить полный цикл загрузки, анализа и отчета.

## Локальный web-интерфейс

```bash
python3 -m safety_helmet_analyzer web --host 127.0.0.1 --port 8080
```

Откройте `http://127.0.0.1:8080`, загрузите один видеофайл и дождитесь отчета.

## Ограничения MVP

- качество распознавания зависит от обученной модели, угла камеры, освещения и
  расстояния до работников;
- спорные случаи стоит помечать как требующие ручной проверки;
- для эксплуатации на объекте рекомендуется собрать примеры с реальных камер и
  дообучить detector backend под конкретные условия.

## Рекомендуемые следующие шаги

1. Выбрать стартовую YOLO-модель или обучить модель на датасете Hard Hat Workers,
   SHWD, Kaggle Hard Hat Detection или Construction Site Safety PPE.
2. Экспортировать модель в ONNX и положить ее в `models/helmet_detector.onnx`.
3. Проверить 10-20 реальных видео с объекта и собрать ошибки модели.
4. Разметить 300-1000 кадров с ваших камер и дообучить модель.
5. Настроить пороги `confidence_threshold`, `min_hits` и `sample_fps` под
   фактическое качество камер.
6. Добавить трекинг работников, batch-обработку видео, PDF-экспорт и журнал
   запусков после подтверждения качества MVP.
