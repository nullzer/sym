# Инструкция по модели, запуску и дальнейшим шагам

Этот документ описывает, как довести MVP до практического локального запуска:
где взять модель, как положить ее в проект, как проверить результат и какие
улучшения запланировать после первой версии.

## 1. Что уже реализовано

Текущий MVP содержит:

- CLI-команду для анализа одного видео;
- локальный web-интерфейс для загрузки одного видео;
- поддержку ONNX detector backend;
- демонстрационный `color` backend без ML-модели;
- агрегацию кадров в эпизоды нарушения;
- HTML-отчет и JSON-отчет;
- сохранение кадров-доказательств;
- unit-тесты бизнес-логики.

Основной результат анализа:

- `reports/<run>/analysis.json` - структурированный результат;
- `reports/<run>/report.html` - отчет для просмотра;
- `reports/<run>/evidence/*.jpg` - кадры с отрисованными признаками нарушения.

## 2. Где взять модель

Для промышленной задачи лучше использовать YOLO-модель, обученную на людях,
касках и головах без касок. Возможны три варианта.

### Вариант A. Готовая модель из открытого проекта

Ищите репозитории по запросам:

- `YOLOv8 hardhat detection best.pt`;
- `helmet detection YOLOv8 ONNX`;
- `construction site PPE detection YOLOv8`;
- `Hard Hat Workers YOLO model`.

Часто готовая модель называется `best.pt`. Ее нужно экспортировать в ONNX:

```bash
pip install ultralytics
yolo export model=best.pt format=onnx imgsz=640
```

После экспорта положите файлы так:

```text
models/helmet_detector.onnx
models/labels.txt
```

Пример `models/labels.txt` для PPE-моделей:

```text
Hardhat
NO-Hardhat
Person
```

Если имена классов отличаются, внесите их в `config/default.json`:

```json
{
  "detector": {
    "person_labels": ["person", "Person"],
    "helmet_labels": ["helmet", "Hardhat", "hardhat"],
    "no_helmet_labels": ["no_helmet", "NO-Hardhat", "head"]
  }
}
```

### Вариант B. Обучение на открытом датасете

Подходящие открытые датасеты:

- **Roboflow Hard Hat Workers** - классы обычно `head`, `helmet`, `person`;
- **Kaggle Hard Hat Detection** - популярный датасет для строительных касок;
- **SHWD Safety Helmet Wearing Dataset** - датасет касок и голов без касок;
- **Construction Site Safety PPE Dataset** - часто содержит `Hardhat`,
  `NO-Hardhat`, `Person`, `Safety Vest`, `NO-Safety Vest`.

Пример обучения через Ultralytics YOLO:

```bash
pip install ultralytics

yolo detect train \
  model=yolov8n.pt \
  data=data.yaml \
  epochs=50 \
  imgsz=640
```

Экспорт:

```bash
yolo export model=runs/detect/train/weights/best.pt format=onnx imgsz=640
```

### Вариант C. Дообучение под объект

Для реальной эксплуатации рекомендуется собрать кадры именно с ваших камер:

- разные смены и погодные условия;
- дневное и вечернее освещение;
- ближние и дальние планы;
- разные цвета касок;
- частичные перекрытия техникой, ковшом, кабиной, тенью;
- примеры людей без каски.

Даже 300-1000 размеченных кадров с объекта могут заметно улучшить качество
после fine-tuning готовой YOLO-модели.

## 3. Подготовка офлайн-среды

На машине с интернетом:

```bash
mkdir wheels
pip download -r requirements.txt -d wheels
pip download ultralytics -d wheels
```

Перенесите на офлайн-машину:

- исходный код проекта;
- папку `wheels/`;
- `models/helmet_detector.onnx`;
- `models/labels.txt`;
- тестовое видео.

На офлайн-машине:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install --no-index --find-links ./wheels -r requirements.txt
pip install -e .
```

`ultralytics` нужен только для обучения/экспорта. Для инференса в текущем MVP
достаточно ONNX-файла, OpenCV и NumPy.

## 4. Запуск анализа

CLI:

```bash
python3 -m safety_helmet_analyzer analyze path/to/video.mp4 \
  --config config/default.json \
  --output reports/run-001
```

Локальный web-интерфейс:

```bash
python3 -m safety_helmet_analyzer web --host 127.0.0.1 --port 8080
```

Демонстрационный режим без модели:

```bash
python3 -m safety_helmet_analyzer analyze path/to/video.mp4 \
  --backend color \
  --output reports/color-demo
```

`color` backend нужен только для проверки полного контура приложения. Он не
заменяет обученную модель.

## 5. Как читать отчет

В `report.html` отображаются:

- общий статус: нарушения обнаружены или нет;
- имя видео и количество обработанных кадров;
- количество подтвержденных эпизодов;
- начало и окончание каждого эпизода;
- количество кадров с нарушением;
- максимальная уверенность;
- причины срабатывания;
- кадры-доказательства.

Основные причины:

- `explicit_no_helmet` - модель явно нашла класс без каски рядом с человеком;
- `standalone_no_helmet_detection` - найден объект без каски без связанного
  bounding box человека;
- `person_without_detected_helmet` - найден человек, но в верхней части его
  bounding box не найдена каска.

## 6. Рекомендуемые настройки

В `config/default.json`:

- `sample_fps`: начать с `2.0`; для быстрых сцен увеличить до `3.0-5.0`;
- `confidence_threshold`: начать с `0.35`; при ложных тревогах поднять до
  `0.45-0.55`;
- `max_gap_seconds`: `1.5` помогает объединять короткие пропуски модели;
- `min_hits`: `2` или `3`, чтобы убрать одиночные ложные кадры;
- `flag_person_without_detected_helmet`: включать, если модель надежно видит
  каски; выключать, если много дальних планов и каски часто не видны.

## 7. Критерии приемки MVP

Перед демонстрацией заказчику:

1. Приложение запускается без доступа в интернет.
2. Одно видео загружается и обрабатывается.
3. Для видео с человеком без каски появляется подтвержденный эпизод.
4. Для видео без нарушений отчет не содержит ложных подтвержденных эпизодов на
   коротком тестовом наборе.
5. В отчете есть таймкоды и кадры-доказательства.
6. Оператор может открыть `report.html` без дополнительных сервисов.

## 8. Следующие этапы

### Технические

- адаптировать ONNX parser под выбранную модель, если формат выходов отличается;
- добавить поддержку Ultralytics `.pt` через отдельный backend, если офлайн-среда
  допускает PyTorch;
- добавить трекинг людей между кадрами, чтобы считать нарушения по одному
  работнику, а не только по кадрам;
- добавить batch-обработку нескольких видео;
- добавить экспорт PDF;
- добавить журнал запусков в локальной SQLite-базе;
- добавить страницу ручной проверки спорных кадров.

### ML/качество

- собрать локальный датасет с реальных камер;
- разметить классы `person`, `helmet`, `no_helmet` или `Hardhat`,
  `NO-Hardhat`, `Person`;
- дообучить YOLOv8n/YOLOv8s или более новую легкую YOLO-модель;
- измерить precision/recall на отложенном наборе видео;
- отдельно проверить дальние планы, сумерки, дождь/пыль и перекрытия техникой.

### Эксплуатация

- определить порог уверенности, при котором событие уходит в отчет;
- договориться, что спорные случаи требуют ручной проверки;
- хранить исходное видео и отчет вместе для аудита;
- фиксировать версию модели и конфиг в каждом отчете;
- ограничить доступ к отчетам, если на видео есть персональные данные.

## 9. Рекомендуемый первый боевой сценарий

1. Взять 10-20 коротких видео с объекта.
2. Запустить MVP с готовой YOLO-моделью.
3. Собрать ложные срабатывания и пропуски.
4. Разметить 300-1000 кадров из этих видео.
5. Дообучить модель.
6. Повторить проверку на тех же видео и сравнить результаты.
7. Только после этого использовать систему как помощника оператора, а не как
   единственный источник решения о нарушении.
